# Ceri engine

Effective disabled state reaches form submission, validation, interaction, and CSS `:disabled` or `:enabled` matching, including the first `legend` exemption inside a disabled `fieldset`.

Every node lives in a document arena with a stable ID and parent and child links, so attached and detached trees share one model. Nodes from `createElement`, `createTextNode` and `cloneNode` can take children, attributes and listeners before insertion, comments and `<template>` contents parse into the tree, and `append`, `prepend`, `before`, `after`, `replaceWith`, `replaceChildren` and `insertAdjacentHTML` gather mixed nodes and strings into a fragment first. Each node has exactly one script handle, so `===` compares nodes and a handle survives any move. That handle is a real object whose prototype chain runs through the DOM interfaces (`HTMLInputElement`, `HTMLElement`, `Element`, `Node`, `EventTarget`, and `Text`, `Comment`, `DocumentFragment` and `Document` for the other node types), so `instanceof`, `name in element`, `Object.keys`, expando properties such as a framework's `__vnode`, and patching `HTMLElement.prototype` work as in a browser. The interface objects are globals with the `Node` type constants; `new Text()`, `new Comment()` and `new DocumentFragment()` construct nodes and the rest throw `Illegal constructor`. Elements also expose `tagName`, `localName`, `namespaceURI`, `attributes`, `hasAttribute`, `toggleAttribute`, `getAttributeNames`, `closest`, `matches`, `contains`, `compareDocumentPosition`, `isEqualNode`, `getRootNode`, `replaceChild`, `insertAdjacentElement`, `insertAdjacentText`, `getElementsByTagName` and `getElementsByClassName`, reflected attributes such as `hidden`, `title`, `name`, `type`, `href` and `htmlFor`, and `template.content`; the document adds `body`, `head`, a writable `title`, `createElementNS` for SVG and MathML, `createComment` and `createDocumentFragment`. Inserting a node into itself raises `HierarchyRequestError`, and a reference from another parent raises `NotFoundError`. `appendChild` and `insertBefore` move nodes without changing their IDs, so listeners, focus and control state follow the node, while removal ends focus and composition inside the subtree. Detached subtrees that no script value reaches are freed at the next microtask checkpoint along with their runtime state; the cycle collector frees cycles among script objects, scopes and arrays, but a detached subtree whose own listeners capture its nodes still stays alive. Live DOM mutations rehydrate select option state after insertion and `innerHTML` replacement, while form ownership follows controls appended after startup. `parentNode`, `parentElement`, and `remove()` expose the tree relationship. Range and Selection follow the DOM standard: a boundary is a node with an offset into its children, or into the UTF-16 units of a text or comment node, and the document moves every live range's boundaries as nodes are inserted, removed, split, merged or have their data replaced. `new Range()`, `setStart()`, `setEnd()`, the `Before` and `After` setters, `selectNode()`, `selectNodeContents()`, `compareBoundaryPoints()`, `isPointInRange()`, `comparePoint()`, `intersectsNode()`, `cloneContents()`, `extractContents()`, `deleteContents()`, `insertNode()`, `surroundContents()` and `createContextualFragment()` are implemented as specified, with `IndexSizeError` for offsets past a node's length. The selection holds one live range with a direction and exposes `anchorNode`, `focusNode`, `type`, `direction`, `getRangeAt()`, `addRange()`, `removeRange()`, `collapse()`, `collapseToStart()`, `collapseToEnd()`, `extend()`, `setBaseAndExtent()`, `selectAllChildren()`, `containsNode()` and `deleteFromDocument()`; `selectionchange` fires once at the next microtask checkpoint for all the changes made since the last one. Events follow the DOM standard's dispatch: an event built by the host or by `new Event()`, `new CustomEvent()`, `new MouseEvent()` and the other interface constructors travels a path from the window down to the target and back up, with capturing listeners first, `eventPhase`, `currentTarget` as `this`, `stopPropagation()`, `stopImmediatePropagation()`, `composedPath()`, and `dispatchEvent()` returning whether the default ran. Listeners take `capture`, `once`, `passive` and `signal` options, may be `handleEvent` objects, and a throwing listener is reported through the window `error` event and the console instead of stopping the others. `onclick`-style properties and inline `onclick="..."` attributes run in their listener slot, and a `false` return cancels. Script can measure the page: `getBoundingClientRect()`, `getClientRects()` (one rectangle per line for inline elements, from the text and boxes inside them), the `offset*`, `client*` and `scroll*` sizes and `offsetParent` come from a layout the runtime runs on demand and reuses until the document or its style state changes, and `getComputedStyle()` returns a snapshot of computed values for layout-backed properties plus declared or initial values for the rest. `matchMedia()` returns a `MediaQueryList` that fires `change` when a resize or a preference flips its answer, `performance` offers `now()`, `timeOrigin`, marks and measures on the page clock, `requestIdleCallback()` runs callbacks with a 50 ms `IdleDeadline`, and `new EventTarget()` and subclasses of it carry listeners like nodes do. Client rectangles follow CSS transforms, with the corners of a transformed box mapped through every transform above it. `MutationObserver` reads a journal the document keeps only while something observes, so `innerHTML`, `textContent`, class and style edits and parser-free inserts all produce records; records are batched per observer and delivered from the microtask checkpoint, with `subtree`, `attributeFilter`, old values and `takeRecords()`. `ResizeObserver` and `IntersectionObserver` compare a fresh layout at each rendering step (after the timers and animation frames of `advance_time`), reporting content and border box sizes, and intersection ratios against the viewport or a root element with `rootMargin` and thresholds; clipping by intermediate scroll containers is not yet considered. `XMLHttpRequest` runs through the same request path as `fetch`, so packaged assets, the resource provider and the external-origin policy apply unchanged; an asynchronous request resolves when `send()` runs and reports `readystatechange`, `progress`, `load` and `loadend` from a task, a synchronous one finishes inside `send()`, and `responseType` covers text, JSON, `arraybuffer` and `blob`. Request timeouts are accepted but cannot fire, because the answer is already there when the task runs. `customElements` defines, upgrades and constructs autonomous custom elements: `document.createElement` runs the class constructor, `super()` hands back the element being created or upgraded, elements already in the document upgrade at `define()`, and `connectedCallback`, `disconnectedCallback` and `attributeChangedCallback` (for `observedAttributes`) run before the DOM call that caused them returns. Customized built-ins (`is=`) are not supported. `<script type="importmap">` maps bare specifiers and URL prefixes, with scopes, for static and dynamic imports, and data blocks such as `type="application/json"` are no longer run as script. Production builds of Preact 11.0.1 (with hooks), Vue 3.5.44 (the global build, compiling in-DOM templates at runtime through `new Function` and `with`) and Svelte 5.57.2 run a counter and a list app in `engine/tests/frameworks.rs`, with their MIT licences beside them in `engine/tests/fixtures`. The Svelte fixture is `App.svelte` compiled once by the Svelte 5.57.2 compiler into `App.js`, plus the 101 runtime modules it reaches and the esm-env 1.2.2 and clsx 2.1.1 files they import, wired together with an import map; the em dashes in the vendored Svelte comments were replaced with hyphens. Module graphs now link the standard way: every module's exports exist before any of them runs, so import cycles such as the one inside the Svelte runtime resolve. `attachShadow()` gives an element an open or closed shadow root: layout renders the host's shadow tree, slots show the light children assigned to them by `slot` name (or their fallback content), a shadow root's `<style>` elements style only that tree plus the host through `:host` and `:host(...)`, page rules stop at the boundary, and composed events cross it through slots and the host with `event.target` retargeted for listeners outside. `::slotted()` and `::part()` are not supported yet; constructable stylesheets are, with `new CSSStyleSheet()`, `replace()`, `replaceSync()` and `adoptedStyleSheets` on documents and shadow roots. Attached node handles resolve through document node IDs, so sibling insertion and attached movement keep existing element and text-node handles attached to the same node.

This crate is Ceri's browser engine, written against the Rust standard library. Its default build has no CEF, WebKit, Servo, third-party JavaScript engine or GUI dependency. The optional `windowed` feature adds `winit` and `softbuffer` for the native window host, and `native-http` adds `ureq` for the HTTPS resource provider.

The engine covers a bounded slice of the web platform. Every unsupported rule, property or API is a named gate in [../docs/engine-research.md](../docs/engine-research.md) rather than a silent failure: unsupported CSS rules are dropped and reported to the page console, and unsupported script surfaces raise typed errors.

How a frame is made, what the engine keeps from one frame to the next, and how to see where a frame's time goes (the `--frames`, `--profile` and `--sweep` switches, and `Performance.getMetrics` over devtools) is in [../docs/frames.md](../docs/frames.md).

The current slice implements:

- HTML tokenization and a small DOM tree built by the tree construction rules: a document always has `html`, `head` and `body`, with head-only elements (`title`, `meta`, `link`, `style`, `script`, `base`, `template`) placed in `head` until body content starts, repeated `html` and `body` tags merging their attributes, and implied end tags for `p`, `li`, `dt`/`dd`, `option`/`optgroup`, headings and table cells, rows and sections (with `tbody` and `colgroup` inserted where a table needs them). An end tag with nothing open to close is dropped, and `</p>` alone makes an empty paragraph. SVG images and markup fragments parse without the implied document elements. Foster parenting, the adoption agency for misnested formatting tags, and RCDATA for `title` and `textarea` are not implemented, and unterminated tags and comments still fail the parse
- HTML entity decoding for common named and numeric entities
- CSS rules with compound tag, class, id and attribute selectors (`=`, `~=`, `|=`, `^=`, `$=`, `*=` and the `i` flag), all four combinators, `:is()`, `:where()`, `:not()`, `:has()` with relative selectors, `:nth-child(An+B of S)`, `:nth-last-child()`, the `*-of-type` family, `:empty`, `:focus-within`, `:active`, `:placeholder-shown`, `:any-link`, `:read-only`, `:read-write`, `:required` and `:optional`; ids and classes keep their case and accept escapes, and pseudo-elements the engine does not draw (`::placeholder`, `::selection`, `::marker` and the like) parse without applying
- a cascade ordered by importance, inline style, specificity and source position, so `!important` wins and a later shorthand overrides an earlier longhand in the same rule
- every CSS Color 4 named color, hex with alpha, `rgb()` and `hsl()` in both syntaxes, `hwb()`, `currentColor` and `color-mix()` in `srgb` and `srgb-linear`
- block boxes with `box-sizing`, `min-width`, `max-width`, `min-height` and `max-height`, `margin: auto` centering, negative margins, collapsing margins between adjacent block siblings and through the top and bottom edges of a parent that has no border, padding, height or formatting context of its own to hold them apart, and percentage heights that resolve only against a definite containing height; the top and bottom margins of an empty block do not yet collapse into each other
- inherited CSS custom properties with `:root` matching, bounded `var()` substitution, fallbacks, cycle rejection, and `calc()` lengths
- document and subtree `querySelector` and `querySelectorAll` lookups using the same selector matcher
- block layout, inline text wrapping, margins, padding, borders, colors, and basic lengths
- fonts by weight (1 to 1000, with `bolder` and `lighter`) and `font-style`, matched to installed faces in the CSS order and drawn with synthetic bold or oblique when no face fits; the `font` shorthand; per-character fallback through the stack's families and then the platform's broad-coverage faces and any installed face that has the character; `@font-face` with `src` lists, `format()`, weight ranges, slant and `unicode-range`, fetched relative to the stylesheet that declares them; TrueType and OpenType CFF outlines (including CID-keyed fonts), and WOFF and WOFF2 files (WOFF2 through the `brotli-decompressor` crate, with the glyf and hmtx transforms rebuilt in the engine). Font collections expose only their first face, and fonts load at navigation, so `@font-face` rules added later by script are not fetched
- text shaping from each font's OpenType tables: GSUB single, multiple and ligature substitutions, chained contexts (format 3) and extensions, standard and contextual ligatures (off when `letter-spacing` is set), Arabic joining forms from the Unicode joining types, GPOS pair kerning (with the legacy `kern` table as a fallback), and glyphs placed at quarter-pixel positions; right-to-left runs shape in logical order and draw from their right edge with mirrored brackets. Mark positioning and Indic reordering are not implemented, so Devanagari and other Indic scripts draw their characters without conjuncts
- colour glyphs: COLR version 0 layers filled from the first CPAL palette (entry 0xFFFF takes the text colour), and PNG bitmaps from CBDT/CBLC strikes (index formats 1 and 3, image formats 17 and 18) and sbix strikes, scaled from the nearest strike at or above the size. Characters in the emoji blocks, and any character followed by U+FE0F, use the platform's colour emoji face (Segoe UI Emoji, Apple Color Emoji or Noto Color Emoji) before the font stack; U+FE0E keeps the text face, and variation selectors take no room. Colour glyphs fade with the text colour's opacity and cast silhouettes for `text-shadow`. COLR version 1 gradients and transforms are not drawn, so faces that carry only version 1 records fall back to their outlines
- the text gate page (`text_gate_page_paints_web_fonts_shaping_colour_decoration_and_wrapping` in `navigation.rs`) loads a WOFF2 and a colour face through `@font-face` and checks, in measured boxes and painted pixels, a ligature against its spaced letters, a kerned pair, colour layers, an underline with a shadow, an ellipsis, `pre`, `pre-wrap`, `pre-line` and an unbreakable word under `overflow-wrap: anywhere`; Arabic, CJK and emoji fallback are checked against the installed system faces in `src/fonts.rs`
- `text-decoration` lines (underline, overline, line-through) in solid, double, dotted, dashed and wavy styles with color and thickness, drawn through descendants' text as well; `text-shadow` (its first shadow), blurred in a layer of its own; `text-overflow: ellipsis` on lines that overflow a clipping block; `::selection` text color; and text field carets, selections and pointer hits measured with the shaped run. Decorations reach into inline-blocks, which browsers do not do
- `white-space` in every mode (`normal`, `nowrap`, `pre`, `pre-wrap`, `pre-line`, `break-spaces`) and its `white-space-collapse` and `text-wrap-mode` longhands, with tabs at eight-space stops; line breaks by the Unicode line breaking algorithm (UAX 14, Unicode 16 tables generated by `engine/tools/text_tables.py`), so ideographs, hyphens and slashes offer breaks; `word-break: break-all` and `keep-all`; `overflow-wrap: anywhere` and `break-word` splitting a word too long for its line; and min-content widths that follow the same rules. Thai and other scripts that need a dictionary do not break inside words
- bidirectional text by the Unicode bidi algorithm (UAX 9) with `direction` and the `dir` attribute: each line's pieces are reordered by embedding level, right-to-left runs are drawn reversed with mirrored brackets, and `text-align: start` and `end` follow the direction. Levels are resolved per text node rather than across a whole paragraph, and `unicode-bidi` is not applied
- `text-align` and `line-height` inherit (a unitless or `normal` line height as a factor, a length as computed pixels), and each line centres its glyph boxes in the line height (half-leading), so inline backgrounds cover the font's ascent and descent
- inline elements as one box per line they land on, carrying background, padding, border, radius and outline (with the start and end edges only on the first and last line), taking pointer hits and reporting their line rectangles to `getClientRects()`; `::before` and `::after` content inside inline elements
- borders per side with `border`, `border-top` through `border-left`, and the `-width`, `-style` and `-color` longhands; every border style (solid, dashed, dotted, double, groove, ridge, inset, outset, and none or hidden taking no space), with corners split between differing sides; `border-radius` per corner with elliptical `/` radii and percentages, shrunk together when they would overlap; backgrounds painted under the border; `overflow` clipping to the padding box that follows rounded corners; and `outline` with `outline-offset`, drawn outside the border box and following its corners; a positioned descendant painted from an outer stacking context is clipped to the rounded box's rectangle only
- `overflow-x` and `overflow-y` (and the two-value `overflow`), with `clip` clipping one axis while the other stays visible, a scrolling axis turning the other's `visible` into `auto`, scrollbars and wheel scrolling only on `auto` axes, and `hidden` boxes scrolling from script only; hit testing that skips the outside of rounded corners
- tables with the automatic layout algorithm (column widths from each cell's minimum and maximum content widths, spread over spanned columns) and `table-layout: fixed`, `colspan` and `rowspan`, header, body and footer groups in that order, anonymous rows for stray cells, `border-spacing`, `border-collapse` (adjacent borders overlap by the widest cell border; per-edge conflict resolution is not implemented), captions on either side, `vertical-align` in cells, row and group backgrounds, auto-width tables shrinking to their columns, and `inline-table`; `<col>` widths are ignored
- list items with outside or inside markers: discs, circles and squares drawn as shapes, and decimal, leading-zero decimal, latin, roman and greek numbering, with `list-style`, `ol start` and `reversed`, `li value`, and nested lists stepping from discs to circles to squares; `::marker` styling and marker images are not supported
- a user agent stylesheet from the HTML standard's rendering section (margins, heading sizes, list and table defaults, monospace and link styles, `hidden`, and form control defaults) that sits below every author rule and layer; elements whose behavior no stylesheet can express (the `hidden` attribute, controls' intrinsic sizes) are handled in code
- drawn form controls: text fields sized by `size`, textareas by `cols` and `rows`, push buttons and submit and reset inputs labelled from `value`, closed selects showing the selected option with an arrow, checkboxes and radios with their checked marks in `accent-color`, range sliders, progress and meter bars, and file inputs with their button; `appearance: none` draws a control as a plain box
- `::placeholder`, `::marker` (color) and `::selection` (background and color) styling; other highlight pseudo-elements parse and do not apply
- `float: left` and `right` with `clear`: floats stack beside earlier floats or drop below them, line boxes in the same formatting context narrow around them and move down when a word or inline box does not fit, boxes that start their own formatting context (`overflow` other than visible, `display: flow-root`, flex and grid containers, inline-blocks, floats and positioned boxes) sit beside floats and grow to contain their own, and floats paint above the in-flow boxes beside them; floats inside one child block do not yet paint above a later sibling's background
- `visibility: hidden` and `collapse`, which keep a box's space but paint none of its background, border, text or outline and take no pointer hits, while descendants set back to `visible` still show
- `cursor` keywords, including the fallback after `url()` images, links showing a pointer, and `auto` showing a text cursor over text and editable fields; the host reports the cursor after each pointer move and the native window applies it
- flexbox following the CSS Flexbox resolution steps: `flex-direction` with the reverse directions, `flex-wrap` with `wrap-reverse`, `flex-grow`, `flex-shrink` and `flex-basis` (and the `flex` shorthand) resolved with min and max clamping and the automatic minimum size, `order`, `row-gap` and `column-gap`, every `justify-content`, `align-items`, `align-self` and `align-content` keyword except baseline (which aligns to the start), auto margins in both axes, `inline-flex`, and anonymous items for text directly inside a container
- bounded CSS positioning for flow-preserving relative visual offsets, `relative` containing blocks, vertical `sticky` descendants tied to the nearest scrollport, `absolute` descendants, viewport-anchored `fixed` descendants, `inset` offsets, and integer `z-index` ordering within layout parents
- layout boxes carry their DOM node ID for coordinate hit testing
- a software paint step with a small built-in bitmap font
- a platform-neutral `EngineHost` frame and input boundary
- a bounded standard-library `EngineWorker` queue that owns browser state off the native event thread; `EngineWorker::spawn_live` keeps the page clock in real time and sleeps until its next due timer or animation change, a command, or a waker from another thread (a command reply or a Web Worker message), and calls the window's waker only when it has an event, so an idle window costs no CPU. On Windows the window presents through a DirectComposition swapchain: a D3D11 device, a flip-model BGRA composition swapchain with premultiplied alpha, and a composition visual on the window, presented on vsync; the software canvas is uploaded into its back buffer, and a window falls back to the softbuffer surface when the device cannot be created. `run_window` opens a list of labelled windows, each with its own live `EngineWorker` thread and browser, and builds each browser with a `WindowContext` that carries the label and a `WindowControl`; the control is a `Send` handle that opens windows by config, closes them by label and delivers host events to every window or one, and the loop ends when the last window closes. A window whose engine fails restarts once, then shows the recovery document, then closes on its own without ending the others. Animations report when their output next changes: a `steps()` animation wakes at its next step, a continuous one every 16 ms frame, a finished one never, and keyframes no element runs do not wake the page
- page-visible dedicated `Worker` objects with packaged or provider-backed same-origin classic and module entry scripts, dedicated threads, bounded structured-cloned messages, `structuredClone()`, `postMessage()`, `addEventListener()`, `onmessage`, `onerror`, `terminate()`, and an explicit host `pump()` boundary
- a platform-neutral accessibility tree with semantic roles, names, values, focusability, disabled state, hidden filtering, and stable node IDs
- an engine-owned JavaScript implementation: an ES2022 parser, a bytecode compiler with names resolved to scope slots, and a stack VM with prototypes, property descriptors, classes with private members, generators, async functions, async generators, and suspending `await`
- DOM events with capture, target and bubble phases through the window, `Event`, `CustomEvent`, `UIEvent`, `FocusEvent`, `MouseEvent`, `PointerEvent`, `WheelEvent`, `KeyboardEvent`, `InputEvent`, `CompositionEvent`, `TransitionEvent`, `AnimationEvent`, `MessageEvent`, `ErrorEvent`, `PopStateEvent`, `HashChangeEvent`, `ProgressEvent` and `SubmitEvent` constructors, `document.createEvent()` with `initEvent()`, and `isTrusted` on host events
- `capture`, `once`, `passive` and `signal` listener options, `handleEvent` objects, `on*` handler properties and inline attributes, and a window `error` event for uncaught exceptions that `preventDefault()` or `onerror` returning true keeps out of the console
- host pointer events with `clientX`, `clientY`, `pageX`, `pageY`, `button` and `buttons`, compatibility `mousedown`, `mousemove` and `mouseup` that a canceled `pointerdown` suppresses, hover `pointerover`, `pointerout`, `pointerenter`, `pointerleave` and their mouse twins, `keydown` and `keyup` with `code`, `repeat` and `keyCode`, and `focusin` and `focusout` with `relatedTarget`
- element attributes, inline styles, and `classList` state mutation
- stable detached and attached element handles with `document.createElement` and `appendChild`
- direct-child `removeChild` with survivor-path preservation, live Range retargeting, listener retention, end-only detached reattachment, and `insertBefore` moves for detached or attached nodes
- bounded `firstChild`, `lastChild`, and `childNodes` access with text-node identity, `nodeType`, `nodeName`, `nodeValue`, `splitText()`, `normalize()`, UTF-16 Range boundary offsets, replacement retargeting, and in-place text-node data mutation

The default build is headless and covers a bounded slice of the web platform. It keeps networking, media, full platform accessibility adapters, WebGPU, and the operating-system window behind optional features or open gates; WebGL is part of the default build. The cascade now carries inherited CSS custom properties, matches the bounded document root with `:root`, resolves bounded `var()` substitutions, fallbacks, and cycles, and evaluates `calc()` lengths before normal declarations reach layout. Positioning is bounded to `relative` containing-block markers, vertical `sticky` visual corrections against the nearest scrollport, `absolute` and `fixed` layout, pixel or percentage `inset` values, flow-preserving relative visual offsets, per-parent integer `z-index` ordering, and atomic stacking layers for positioned z-index boxes and fixed boxes. Element and document scrolling are bounded to one overflow mode, a classic-style 12px scrollbar gutter with software-painted tracks and thumbs, software paint and hit-test clipping, scroll offsets, wheel deltas, and synchronous `scroll` events. Horizontal or inline sticky descendants, full sticky containment edge cases, complete CSS stacking-context semantics, smooth scrolling, and scroll snapping remain separate gates. The scrollbar gutter is reserved after the bounded layout pass, so it does not claim full CSS reflow compatibility. WebAssembly is limited to the bounded i32 module path listed above. The optional `native-http` feature adds a Rust-native HTTPS `ResourceProvider` with platform certificate verification, bounded redirects, connection reuse, and a 30-second request timeout. Its API is blocking, so the native window adapter uses `EngineWorker` to keep browser state and provider calls off the UI event thread. The worker queue is bounded and drops new input when saturated instead of growing without limit.

`Browser::with_resource_provider` keeps the renderer independent of transport. The engine resolves and validates the app-origin URL, checks the packaged bundle first, and asks the provider only when that bundle misses. The provider can read a signed package, a native HTTP/TLS client, or another host-owned source. It never needs to open a listener, and it cannot receive a cross-origin `AppUrl` because the URL parser rejects those references before the provider call. Extensionless document routes use the same `/index.html` shell fallback as packaged assets.

With `--features native-http`, `NativeHttpProvider::new("https://example.com/app")` maps the engine's owned `https://app.ceri.invalid` paths onto that HTTPS origin. It rejects insecure and credentialed bases, leaves redirect policy to the engine by disabling automatic redirect following, preserves response status and headers for `fetch()`, and limits response reads through ureq's bounded body reader. Navigation follows a bounded chain of same-origin relative locations and rejects cross-origin redirects. Redirected modules resolve their relative imports from the final module URL. The provider is an opt-in transport adapter, not a loopback server or a renderer dependency.

Hosts can inspect `Browser::last_navigation_failure()` or `EngineHost::last_navigation_failure()` after a recovery page is installed. The diagnostic carries the app URL, HTTP-style recovery status, and typed detail. An upstream provider status reaches the recovery page unchanged, a provider transport failure becomes status 503, missing assets remain status 404, and parser or script failures remain status 500.

`fetch(url, options)` accepts the deterministic request subset needed by a native provider: a URL string or `Request`, `method`, an object or mutable `Headers` instance for `headers`, a string, `ArrayBuffer`, `Blob`, `File`, `URLSearchParams`, or `FormData` `body`, the standard cache modes, a `redirect` mode of `follow`, `error`, or `manual`, and an `AbortSignal`. String, `Blob`, `File`, `URLSearchParams`, and `FormData` bodies infer `Content-Type` when the page did not supply one. FormData bodies use deterministic multipart encoding with ordered text and File entries, filenames, per-file content types, and a collision-safe boundary. `new Request(input, init)` exposes normalized `url`, `method`, `headers`, `cache`, `redirect`, `signal`, `bodyUsed`, `clone()`, `text()`, `blob()`, `formData()`, and `arrayBuffer()` state, and `fetch(request)` inherits its method, headers, body, cache, redirect, and signal values unless init overrides them. `new Response(body, init)` exposes `type`, `url`, `status`, `statusText`, `ok`, `redirected`, `headers`, `bodyUsed`, `clone()`, `text()`, `json()`, `blob()`, `formData()`, and `arrayBuffer()`, with mutable headers for script-created responses and immutable headers for fetched responses. `formData()` parses `application/x-www-form-urlencoded` bodies and deterministic `multipart/form-data` bodies into ordered text and File entries. `Response.json(data, init)` serializes a runtime value and supplies `application/json` when the init headers do not set a content type. `Response.error()` creates an immutable type-error response with status 0. `Response.redirect(url, status)` creates an immutable same-origin redirect response with a normalized `Location` header for status 301, 302, 303, 307, or 308. `new Headers()` accepts objects, pair sequences, or another `Headers` instance, and exposes normalized `append()`, `set()`, `delete()`, `get()`, `has()`, key, value, and entry iteration, and `forEach()`. Header names are normalized and control characters are rejected. Packaged GET resources are resolved locally; other requests cross the `ResourceProvider::provide_response` hook with their cache mode intact. The page can read the provider's status, MIME type, and normalized headers through the response. An aborted signal rejects before the provider is called, and listeners receive one deterministic `abort` event. Response bodies are single-use across `text()`, `json()`, `blob()`, `formData()`, and `arrayBuffer()`. `response.clone()` copies the unread body and metadata into an independent response, and rejects after the source body is locked, disturbed, or consumed. `response.body` returns one stable stream object for the response. Its `getReader()` exposes fixed byte chunks, `read()`, `releaseLock()`, `cancel()`, `locked`, and `done` state. `response.body.tee()` clones the unread bytes into two independently readable branches and locks the source body. Follow mode reports the final URL and `redirected = true`, manual mode returns the redirect response, and error mode rejects. Redirected POST requests use the engine's standard method rewrite rules. `caches` is a bounded in-memory session store: `open()`, `has()`, `delete()`, `keys()`, and cross-cache `match()` manage named caches, while each cache stores GET or HEAD response snapshots through `put()`, `match()`, `delete()`, and `keys()`. Full stream backpressure, BYOB readers, and TLS policy stay with future compatibility gates.

FormData bodies use deterministic multipart encoding with ordered text and File entries, filenames, per-file content types, and a collision-safe boundary. `FormData` exposes ordered `keys()`, `values()`, `entries()`, `forEach()`, and `Symbol.iterator` views over those entries.

`URLSearchParams` exposes the same ordered key, value, entry, `forEach()`, and `Symbol.iterator` views, including duplicate pairs and updates back to its owning `URL`.

`new Worker(url, { name, type })` resolves a same-origin classic or module entry script from the packaged resource bundle or the embedder-owned `ResourceProvider`. Classic Workers can call `importScripts()` sequentially, while module imports and `fetch()` calls inside either Worker type use the same packaged-first policy. Provider requests cross a bounded host-owned bridge and are serviced by `Browser::pump()` or `EngineHost` on the engine thread. The worker has `self.addEventListener("message", callback)`, `self.onmessage`, `postMessage()`, `fetch()`, and `globalThis`, with `importScripts()` available only to classic Workers. The page has `worker.addEventListener()`, `worker.postMessage()`, `worker.onmessage`, `worker.onerror`, `worker.name`, `worker.url`, and `worker.terminate()`. Messages cross the thread boundary as bounded structured-cloned values through a queue, using the same primitive, collection, binary, Blob, File, and Error types as `structuredClone()` and IndexedDB. An `ArrayBuffer` in a transfer list moves to the receiver; cycles, shared-reference identity, and nested workers remain outside this slice.

Scripts run on the engine's own JavaScript core. The parser accepts the ES2022 grammar for scripts and modules, including regular expression and template literals, tagged templates, destructuring, spread, optional chaining, classes with fields, private names and static blocks, labelled statements, `switch`, every loop form, and `try`/`catch`/`finally`. Code compiles to bytecode in which each name is resolved to a slot in a chain of heap scopes, so closures share their scope instead of copying it, and calls between script functions stay in one loop rather than on the Rust stack. Objects keep insertion order with integer keys first, data and accessor properties with attributes, and prototype chains; `Object`, `Function`, `Symbol`, `Boolean`, `Number`, `String`, `Array` and the `Error` family are real function objects with their prototypes. Generators and async functions suspend their frame and resume it later, so `await` waits on a pending promise across tasks, promises adopt thenables, and `for await`, async generators and top-level `await` in modules work. Host values such as elements, collections and responses keep their existing native types and fall back to the matching prototype for anything they do not define, so reading an unknown property returns `undefined`. Uncaught errors carry the thrown value; host API failures surface as `TypeError` or a named `DOMException`, and an error thrown by a timer or `queueMicrotask` callback is reported to the console without stopping the clock. Strings index by UTF-16 code unit, as `length`, `charCodeAt` and the slicing methods expect. The standard library covers the full `Array.prototype` (including the ES2023 copying methods and a stable sort that tolerates inconsistent comparators), `String.prototype` with regular-expression `match`, `matchAll`, `replace`, `replaceAll`, `search` and `split`, `Math`, `Number.prototype.toFixed`, `toPrecision`, `toExponential` and `toLocaleString` with exact decimal rounding, `parseInt` and `parseFloat`, `JSON.parse` with a reviver and `JSON.stringify` with `toJSON`, replacers, indentation and cycle detection, `Promise.all`, `allSettled`, `race`, `any`, `withResolvers` and `finally`, `setInterval` and `queueMicrotask`, and a `console` with format specifiers, value inspection, groups, counters, timers and `assert`. The packaged SVG demo exercises a dependency-free image path:

Images decode inside the engine with no image library. PNG covers every color type and bit depth, palettes with `tRNS` transparency, all five scanline filters and Adam7 interlacing, through an engine-owned zlib inflater that checks every chunk CRC and the Adler-32 trailer. JPEG covers baseline and progressive Huffman coding with 8-bit samples, any sampling factors, restart intervals, Adobe CMYK and YCCK, and EXIF orientation; arithmetic, lossless and 12-bit files are refused. GIF decodes the first frame with its transparent index and interlaced rows. Broken, unsupported, or cross-origin image references stay absent from the frame instead of escaping the resource boundary.
