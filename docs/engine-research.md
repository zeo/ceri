# Browser engine research

Research snapshot: 2026-10-16

The custom DOM path now covers live text-node `splitText()` and `normalize()` operations, including identity-preserving merges, empty-node removal, and Range boundary retargeting. CharacterData substring and mutation methods share the UTF-16 edit path and preserve the same live ranges. Sibling navigation, element-only sibling navigation, and `isConnected` resolve through the same stable node identity after removal. `document.createTextNode()` can create detached text, run UTF-16 CharacterData methods, split it, attach it through the existing element insertion boundary, and move attached text between parents. `cloneNode()` creates shallow or deep detached copies without copying listeners. Element serialization now exposes `outerHTML` alongside `innerHTML` for attached and detached elements, and writable `outerHTML` replacement parses a fragment, preserves the old handle for reattachment, and retargets removed-subtree state through the same path. Direct children of the document and detached elements keep the standard no-parent rejection. `append()` or `prepend()` route mixed string and node arguments through the same identity-preserving insertion path. `replaceChildren()` removes direct children through the same live detach path and reattaches any passed handles with their listeners. `before()` and `after()` insert mixed siblings through the same path, while `replaceWith()` inserts replacements and detaches the anchor through the same Range and listener path. `insertAdjacentHTML()` parses and inserts fragments at all four positions through that path. The script runtime now also exposes bounded `ArrayBuffer` and `Uint8Array` byte values with shared backing buffers, byte-offset and length views, copying `slice()`, sharing `subarray()`, and `crypto.subtle.digest()` for SHA-1, SHA-256, SHA-384, and SHA-512 over either type, while key generation, encryption, signing, verification, and secure randomness remain future gates.

## Decision

The custom runtime now has bounded IndexedDB and an optional persistent storage bucket. `indexedDB.open()` and `deleteDatabase()` return callback-based requests, version upgrades expose `upgradeneeded`, and readonly or readwrite transactions expose object-store creation, deletion, and structured-cloned `put()`, `add()`, `get()`, `delete()`, `clear()`, `count()`, `getAll()`, and `getAllKeys()` operations. The shared clone path covers primitives, arrays, plain objects, `Map`, `Set`, `ArrayBuffer`, `Uint8Array`, `Blob`, `File`, and `Error` values, with fixed depth, node, string, and byte limits. `structuredClone()` and Worker messages use the same path. Database and object-store state survives full-document navigation in one browser session. A host can pass `Browser::with_storage_directory()` to reload localStorage, CacheStorage, and IndexedDB from a versioned atomic snapshot on the next browser instance, with a reader for the prior JSON record format and a writer for the current clone-tag format, while sessionStorage remains session-only. The storage bucket is origin-scoped by the engine's fixed app origin and rejects malformed or oversized snapshots before use. Transfer lists, cycles, shared-reference identity, indexes, and cursors remain separate gates.

The Rust-native engine is now the only engine. The runtime serves the packaged app through the asset-origin policy, renders it with installed system fonts at the display device pixel ratio, applies every rule in the app stylesheet without dropping any, reaches `4 / 4` on the continuity page, and ships as a 5.7 MB bundle of nine files with a 28 MB working set while the app is open and animating. The CEF bundle it replaced was 411 MB across 252 files and held 319.7 MB resident across six processes.

CEF was removed on 2026-10-16 instead of being kept as a fallback. Two engines meant two security surfaces, two bundling paths and a bridge written twice, and the fallback hid every gap in the native engine instead of forcing it closed. An app that needs one of the gates below now waits for that gate:

- media playback, WebGL and other GPU APIs
- cross-origin policy beyond an operator allowlist, so there is no CORS preflight, no cookie jar and no credential mode
- `transform-style: preserve-3d`, so intersecting 3D planes are not depth sorted and each transformed element flattens on its own
- transitions between shorthand and longhand declarations, so a `margin` change does not drive a `margin-top` transition, and between `box-shadow` lists of different lengths
- full WebAssembly beyond the bounded i32 module path
- multi-process renderer isolation and a per-renderer sandbox; the plan is one renderer process per window under a Windows job object and restricted token
- platform accessibility adapters, so the accessibility tree has no UIA, AT-SPI or NSAccessibility bridge yet
- any browser-compatibility suite result, including web-platform-tests

The Servo comparison track stays open for the layers where growing our own engine is the worse trade, particularly GPU-backed compositing and media.

Pointer selection now covers prose outside form fields. A press over a text run collapses the document selection to that spot, a drag extends it, and layout tags each run with the DOM text node and UTF-16 offset it came from so hit testing resolves to node-and-offset boundaries even across word-wrapped runs. Selected spans paint as highlight rectangles behind glyphs with widths measured in the active font, and Ctrl or Cmd with C copies the selection through the host clipboard seam when no editable control has focus. The selection keeps a separate anchor and focus, so a backward drag holds the press point, and `Selection.extend()`, `setBaseAndExtent()`, `direction`, `anchorNode` and `focusNode` report the same state to scripts. A range that crosses text nodes paints one span per node, and copy rebuilds the text from the laid-out runs, so hidden, `<script>` and `<style>` text stays out and blocks are separated by line breaks. The host counts presses inside 500 ms and 4 px as one series: `click` carries `detail`, the second press fires `dblclick` and selects a word, the third selects the block, and a drag after a double click extends by words. Word boundaries come from a small segmenter that keeps letters, digits, underscores and inner apostrophes together and treats each CJK ideograph as one word. Shift with arrows, Home and End extends prose by character, word or visual line, Ctrl or Cmd with A selects every rendered run, and the same segmenter drives Ctrl word movement and deletion in text controls. A press on a scrollbar thumb no longer starts a selection, and a press on empty space clears it. Bidirectional text, grapheme clusters beyond surrogate pairs, and dictionary-based word breaking for scripts without spaces remain open.

That gives three separable goals:

1. Ceri owns its desktop runtime and app protocol. Shipped.
2. Ceri can drive an engine through a stable adapter boundary. Shipped: the `EngineHost` frame and input boundary, `ResourceProvider`, `FilePicker`, `ClipboardProvider` and `FontSource` seams, plus the shared native window host.
3. Ceri's own engine covers enough of the web platform for the apps that use it. It is the only engine now, and the gate list above is the remaining work.

## Candidates

| Candidate | What it gives Ceri | Main gap | Decision |
| --- | --- | --- | --- |
| CEF with Chromium | Broad current web compatibility, multi-process isolation, GPU, media, DevTools, and desktop binaries | Large bundle and Chromium upgrade work | Removed on 2026-10-16; its measurements stay as the baseline |
| Servo | Rust implementation, an embedding `WebView` API, WebGL and WebGPU, and Windows, macOS, Linux, Android, and OpenHarmony targets | Embedding documentation is still sparse, media needs GStreamer, the public API is evolving, and Servo has no 1.0 release or specific security guarantees | Keep as a comparison backend |
| Ladybird | A genuinely independent engine built from scratch with no Blink, WebKit, or Gecko code | The project is targeting its first 2026 alpha on Linux and macOS, and it is primarily a browser project rather than an embeddable desktop runtime | Track for research, not a Ceri backend yet |
| WPE WebKit | A focused embedded WebKit port with hardware-accelerated rendering and media support | WPE currently runs on Linux-based systems, and WebRTC is disabled in official release tarballs by default | Useful Linux comparison, not the all-platform engine |
| New engine written by Ceri | Full ownership of architecture and policy, and a bundle two orders of magnitude smaller | Full browser-engine scope, long compatibility tail, and no security history | The shipping engine |

The Servo embedding chapter explicitly says its documentation is sparse and still in progress. It also documents that common desktop media support requires the GStreamer feature and platform libraries. Servo's LTS guidance says the library has no 1.0 release and is provided on a best-effort basis without specific security guarantees. Those are acceptable conditions for an isolated experiment and unacceptable conditions for silently replacing the production backend.

WPE's architecture is attractive for embedded Linux because it separates WebKit from the final rendering backend. Its own FAQ says the port currently works only on Linux-based operating systems, so it cannot satisfy Ceri's desktop target by itself. WebKit's port documentation also warns that there are no cross-platform WebKit releases, each port publishes its own builds and security advisories.

Ladybird is the most interesting independent-engine project to watch. Its public project page describes a from-scratch engine and sets the first alpha target for Linux and macOS in 2026. That makes it useful for studying independent browser architecture, while its current milestone keeps it outside Ceri's compatibility baseline.

## Adapter boundary

The production app contract does not expose engine internals. The browser implementation sits behind a small native boundary with these responsibilities:

- create and destroy a top-level view
- load an application URL from an embedder-owned asset source
- deliver input, resize, focus, clipboard, and IME events
- report navigation, title, load, console, and renderer-failure events
- evaluate only explicitly registered host capabilities
- paint or present frames through a platform-owned surface
- terminate and recover a renderer without changing the app origin
- expose typed navigation and recovery diagnostics to the native host

The asset resolver, `https://app.ceri.invalid` origin, SDK response shapes, recovery documents, and host-owned `ResourceProvider` contract stay engine-neutral, so a future Servo adapter could use the same application contract without making Servo a production dependency.

The provider seam is now exercised by host-backed integration tests covering the document, stylesheet, module graph, JSON fetched by the page, and a POST request with normalized headers, a body, a 201 response, and response header membership, lookup, and iteration. The script runtime can construct mutable `Headers` values from objects, pair sequences, or another `Headers`, construct and clone `Request` objects, inspect their URL and method state, pass them through `fetch`, construct script-owned `Response` objects with status, status text, mutable headers, JSON serialization, error responses, and same-origin redirects, and retain an immutable response-header view for fetched resources. `AbortController` and `AbortSignal` now carry structured reasons, abort events, and deterministic preflight rejection through the fetch surface. Response bodies now have shared single-use state, `arrayBuffer()`, and a bounded default `ReadableStream` reader. The optional `native-http` feature adds a Rust-native HTTPS provider while keeping transport outside the renderer. Recovery pages also expose a typed URL, status, and detail diagnostic, so a native adapter does not need to scrape the document to classify a failed load. The renderer now reevaluates a bounded viewport-aware `@media` subset during layout, which is the first responsive cross-window gate.

## Compatibility gates

The script runtime no longer walks a syntax tree. A new core under `engine/src/script/` lexes and parses the full ES2022 grammar for scripts and modules, compiles each function to bytecode with names resolved at compile time to (depth, slot) pairs on a chain of heap scopes, and runs it on a stack VM. Script-to-script calls push frames inside one loop; generators and async functions keep their suspended frame on the heap, which is what lets `await` wait on a promise that settles in a later task and lets `for await`, async generators and top-level module `await` work. `try`/`finally` routes `return`, `break`, `continue` and throws through finally blocks at run time. Objects store properties in insertion order with integer keys first, with data and accessor properties carrying writable, enumerable and configurable attributes, and every object has a prototype link; the intrinsic constructors are function objects, classes support fields, private methods and accessors, static blocks, `super` and `new.target`, and `instanceof` walks the prototype chain. Host values keep their native representations and inherit from the matching intrinsic prototype, so unknown properties read as `undefined` instead of raising. Promise resolution adopts thenables, rejections carry the thrown value, and host failures become `TypeError` or `DOMException` values. The [ECMAScript 2022 specification](https://tc39.es/ecma262/2022/) is the reference for the conversions and operators. The standard library now has the array, string, number, math, JSON, console and promise-combinator surface, and regular expressions run on an engine-owned backtracking matcher over UTF-16 code units, compiled to a small instruction set with an explicit backtrack stack (so long subjects cannot overflow the Rust stack) and a step limit; compiled patterns are cached per source and flags, so a literal inside a loop compiles once. `Number.prototype.toFixed` and its siblings round the exact decimal expansion of the double, so ties such as `(2.5).toFixed(0)` and `(1.005).toFixed(2)` match other engines. Collections hash their keys by SameValueZero identity (nodes by their single handle, so a `WeakMap` keyed by an element finds it again) and keep tombstones while an iteration is live, so iterators observe additions and deletions the way the spec describes, compacting once no iteration holds a position. `Proxy` traps are consulted inside the property algorithms themselves, so a proxy works anywhere an object does: property access, `in`, `delete`, spread, `Object.keys`, `JSON.stringify`, `for...in`, calls and `new`. `Date` local time comes from an embedder seam because the engine stays free of platform code; the desktop runtime implements it with `SystemTimeToTzSpecificLocalTime` on Windows and `localtime_r` elsewhere. `BigInt` now runs on an engine-owned arbitrary-precision integer. `String.prototype.normalize` runs on tables generated from the Unicode 16.0 character database. The milestone's gate is a pinned test262 subset (tc39/test262 at `d53ebc8b`, checked in under `conformance/test262`): 21,127 of 28,695 non-module tests pass, 73.6%, with String at 94.8%, Number at 97.4%, Date at 94.1%, Object at 85.2%, Array at 68.1%, Promise at 43.7% and `language/expressions` at 78.9%. The runner caught two engine panics in `Array.prototype.copyWithin` when argument coercion shrinks the array, and infinite loops in collection constructors and `Promise` combinators that collected an iterable before closing it; all three are fixed. What remains is listed in `expected-failures.txt` and summarized in the engine README; `Intl` locales beyond English and the main European ones also remain.

The runtime now carries effective disabled paths into CSS matching, so `:disabled` and `:enabled` agree with form submission, validation, focus, click suppression, disabled `optgroup` state, and the first `legend` exemption inside a disabled `fieldset`.

The selector slice now accepts top-level selector lists in stylesheets and DOM queries, preserves commas inside attribute values and functional pseudo-class arguments, and matches bounded `:not(...)` arguments with their selector specificity. Selector lists with invalid entries remain rejected as one rule, matching the current parser's fail-closed policy.

Form activation now carries `POST` submissions through the typed `ResourceProvider` seam. The engine serializes named controls as `application/x-www-form-urlencoded`, keeps the request off any loopback listener, follows bounded same-origin redirects with the standard 301, 302, 303, 307, and 308 method rules, and parses the final HTML as a new history document. Packaged-only POST actions resolve to an engine-owned 503 recovery page because there is no transport boundary to receive them.

Labels now resolve an explicit `for` reference or the first labelable descendant. A permitted click on label text forwards focus and activation to that control, while prevented clicks and interactive label descendants stay local to the original target.

After page scripts run, the navigation path applies the first valid document-order `autofocus` candidate unless script startup already selected a focused element. Disabled, hidden-type, and non-focusable candidates are skipped.

The same runtime keeps read-only text controls focusable and form-visible. Their `readOnly` IDL state can change from script, selection movement remains available, and host typing, deletion, Enter editing, and composition updates leave the live value unchanged while the control is read-only.

Host edits and IME composition now honor `maxlength` in UTF-16 code units, including surrogate-pair boundaries and textarea Enter insertion. Script value writes remain separate from this host-input cap.

The form path now exposes a bounded constraint-validation surface. `required` checks empty mutable controls, dirty-value `minlength` and `maxlength` set `tooShort` or `tooLong`, email and URL controls set `typeMismatch`, common anchored `pattern` expressions set `patternMismatch`, `setCustomValidity()` sets `customError`, and controls expose `validity`, `willValidate`, `validationMessage`, `checkValidity()`, and `reportValidity()`. The pattern matcher accepts literals, character classes, escapes, ranges, and quantifiers without adding a regex dependency; unsupported pattern syntax is treated as an invalid pattern and ignored. Form `checkValidity()` and submission walk the existing packaged control paths, fire non-bubbling `invalid` events at failing controls, and hold navigation until the constraints pass. The shape follows the [WHATWG form-control infrastructure](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html) and [form submission and validation rules](https://html.spec.whatwg.org/multipage/forms.html); range-specific states remain outside this slice.

Form reset now follows the same in-document boundary. `form.reset()` and `input` or `button` reset controls fire a cancelable bubbling `reset` event, guard against recursive reset calls, and restore the current input, textarea, checkbox, radio, and file state without dispatching synthetic input events. `defaultValue` and `defaultChecked` update the page's defaults while preserving a dirty live value or checkedness until reset. The reset algorithm follows the [WHATWG form reset rules](https://html.spec.whatwg.org/multipage/forms.html) and [input reset rules](https://html.spec.whatwg.org/multipage/input.html); output-specific reset remains outside this slice.

Form ownership now resolves the nearest ancestor `form` or an explicit `form` attribute that names a form in the document. `form.elements`, FormData construction, constraint validation, focus, and click suppression all use that owner. A disabled `fieldset` bars descendant controls except those inside its first `legend`, so the same effective disabled state applies to submission and validation. The association and disabled-state rules follow the [WHATWG form-control infrastructure](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html).

Select controls now keep option selectedness separate from content attributes. The bounded script surface exposes `value`, `selectedIndex`, `options`, `selectedOptions`, `multiple`, `option.selected`, `option.defaultSelected`, `option.value`, `option.text`, and `option.index`. Single-select fallback selection, multiple selections, required-select placeholder validation, disabled `optgroup` filtering, ordered FormData entries, and reset to `selected` defaults are covered. Native select popovers, pointer or keyboard option picking, full option rendering, and output-specific reset remain separate gates. The selectedness, disabled-option, and required-select rules follow the [WHATWG select and option algorithms](https://html.spec.whatwg.org/multipage/form-elements.html).

The same select state now follows live DOM changes. Appending detached options or option groups initializes only the new options and preserves existing script-selected state, while `innerHTML` replacement rebuilds affected selects from current default attributes and drops stale option state. Form ownership remains query-driven, so controls appended under one subtree can resolve an explicit owner form elsewhere in the document.

The DOM is now an arena of nodes with stable IDs and parent links instead of a value tree addressed by child-index paths. `removeChild` unlinks a node and leaves nothing behind, so survivors keep their positions without any path shifting, and runtime state such as listeners, control values and scroll offsets is keyed by node ID. A removed subtree stays usable while script holds a handle to it and can be reinserted anywhere, with select normalization rerun after option removal or insertion; an unreachable one is freed with its runtime state at the next microtask checkpoint. Event listeners belong to the node, so they follow it through removal and reinsertion. `appendChild` and `insertBefore` move nodes between parents or within one parent while preserving node IDs, listeners, focus, selection, and form-control state. Style matching and layout walk the arena directly, which also brought the packaged page's median frame from about 3.4 ms to 2.7 ms. Range boundaries hold live node handles, so bounded element-text ranges span siblings, text-node boundaries use UTF-16 offsets, and insertion or movement preserves the referenced nodes. Text and `innerHTML` replacement retarget descendant endpoints to the containing element and remap ancestor UTF-16 offsets. Text-node data, `nodeValue`, and `textContent` setters keep the text node identity and adjust live offsets in place, `splitText()` moves boundaries to the new right-hand node, and `normalize()` merges contiguous text nodes, removes empty text nodes, and retargets live boundaries.

Attached elements also expose `parentNode`, `parentElement`, and `remove()`. Detached handles return `null` for both parent properties, so scripts can observe the transition after removal without opening a transport or listener.

Nodes and the window share one listener registry and one dispatch routine that follows the [DOM standard's dispatch algorithm](https://dom.spec.whatwg.org/#concept-event-dispatch): the path runs from the target through its ancestors to the window (except for `load`), capturing listeners run on the way down and at the target before non-capturing ones, and bubbling listeners run on the way up. Events are objects with interface prototypes, so `event instanceof MouseEvent`, subclassing `CustomEvent` and expando properties behave as in a browser. Duplicate registrations are ignored, removal matches the callback and capture flag, `{ once: true }` listeners are removed before their callback runs, `{ passive: true }` makes `preventDefault()` a no-op, and `{ signal }` listeners are removed before the `AbortSignal`'s abort event. A listener that throws is reported through the window `error` event, as the HTML standard's [report the exception](https://html.spec.whatwg.org/multipage/webappapis.html#report-the-exception) step describes, and the rest still run. The host fills `PointerEvent` coordinates and buttons, follows each pointer event with its compatibility mouse event per [Pointer Events](https://www.w3.org/TR/pointerevents/), fires over, out, enter and leave events as the hovered node changes, and passes winit's physical key code through as `KeyboardEvent.code`. Workers keep their own listener lists; the page's `Worker` and `AbortSignal` objects receive real `MessageEvent`, `ErrorEvent` and `Event` objects.

The same form path now accepts `enctype="multipart/form-data"` and reuses the deterministic multipart encoder already used by script-created `FormData` requests. Text fields preserve order, quoted parameter escaping, and collision-safe boundaries. A host-owned `FilePicker` supplies validated file names, MIME types, bytes, and modification times without exposing filesystem paths to the renderer. File controls expose `files`, `FileList.item()`, the standard fake path display value, input and change events, picker cancellation, and multipart `File` entries, including the empty-file entry when no file is selected.

The clipboard boundary now follows the same host-owned pattern. `ClipboardProvider` backs secure-context `navigator.clipboard.readText()` and `writeText()` calls with fulfilled or rejected promises, so the renderer receives text values without a platform clipboard handle. A host can reject access for permission, user-activation, or unavailable-platform reasons without changing the script surface.

Text controls now keep a bounded UTF-16 selection model for `input` text-like states and `textarea`. The script surface includes `select()`, `selectionStart`, `selectionEnd`, `selectionDirection`, `setSelectionRange()`, and `setRangeText()` with `select`, `start`, `end`, and `preserve` modes. Host text insertion and Backspace, Delete, Home, End, arrow-key editing, and Enter line breaks in `textarea` operate on the live selection, and selection changes fire `select` and text-control `selectionchange` events. Host edits and composition are capped by `maxlength` in UTF-16 code units, while script value writes remain separate. Empty controls paint the short `placeholder` hint while their live value remains empty. Password controls paint masked display characters while retaining their live value and UTF-16 selection. Read-only text controls remain focusable and submittable, allow selection movement, and reject host edits and composition updates. Sequential focus navigation now maps Tab and Shift+Tab through the same focusable controls, with positive `tabindex` entries first and negative entries excluded. The offsets and range rules follow the [WHATWG text control selection APIs](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html). Modifier-key extension, document `Selection` and `Range`, document `selectionchange`, and software paint for single-line input values plus textarea values with explicit line breaks are now covered, with the caret following forward or backward selection direction. Textarea soft wrapping follows content width and honors `wrap="off"`. Word-aware line breaking, caret blinking, and native candidate-window positioning remain separate gates.

The native input boundary now carries winit modifier state, preedit, commit, and disable notifications into the custom runtime. `keydown` exposes `shiftKey`, `ctrlKey`, `altKey`, and `metaKey` from the [UI Events KeyboardEvent contract](https://www.w3.org/TR/uievents/); Shift plus Left, Right, Home, or End extends a text-control selection while preserving UTF-16 boundaries and direction. Tab and Shift+Tab run sequential focus navigation with positive `tabindex` ordering, negative entry exclusion, and blur/focus dispatch. Empty controls paint their `placeholder` hint without mutating the control value. `document.createRange()`, `document.getSelection()`, and `window.getSelection()` now cover bounded element and text-node content across siblings with `firstChild`, `childNodes`, `setStart()`, `setEnd()`, `selectNodeContents()`, bounded UTF-16 offsets, `cloneRange()`, `collapse()`, `addRange()`, `getRangeAt()`, and stringification. Range endpoint handles remain live through sibling insertion and attached movement, while text replacement clamps stringification to current content. Text and `innerHTML` replacement retarget descendant endpoints to the containing element and remap ancestor UTF-16 offsets. Text-node `data`, `nodeValue`, and `textContent` setters keep the node identity and adjust live Range offsets in place, while `splitText()` moves boundaries to the new right-hand node. Single-line input values and explicit-line textarea values use the same layout state for text, selection highlights, and the software caret, with the caret following the selection direction. Enter inserts a line feed in focused `textarea` controls through the same selection replacement path, subject to `maxlength` in UTF-16 code units. Textarea soft wrapping follows content width and honors `wrap="off"`. Text-control and document `selectionchange` listeners run when those bounded selections change. Text controls dispatch `compositionstart`, `compositionupdate`, and `compositionend`, replace the active preedit range during updates, expose `event.data` and `event.isComposing`, commit final text through the live selection, and restore the selection when a composition is canceled. Word-aware line breaking, caret blinking, and candidate-window positioning remain separate gates.

The current fetch experiment includes shared single-use response bodies, `arrayBuffer()`, `blob()`, `formData()`, `clone()`, `follow`/`manual`/`error` redirect modes with final URL state, a bounded `Request` constructor with URL, method, headers, cache, redirect, signal, `bodyUsed`, body cloning, single-use text, blob, formData, or byte reads, and string, `ArrayBuffer`, `Blob`, `File`, `URLSearchParams`, or `FormData` bodies with inferred content types, a bounded `Response` constructor with status, status text, type, mutable script-created headers, `Response.json()`, `Response.error()`, same-origin `Response.redirect()`, and immutable fetched headers, mutable request `Headers` with constructor, `append()`, `set()`, `delete()`, `get()`, `has()`, key, value, and entry iterators, `forEach()`, and normalized response headers. Immutable `Blob` and `File` values support byte-part construction, MIME type normalization, file names and timestamps, slicing, text and `ArrayBuffer` reads, and request or response body integration. FormData bodies use deterministic multipart encoding with ordered text and File entries, filenames, per-file content types, and a collision-safe boundary. `formData()` parses `application/x-www-form-urlencoded` and deterministic `multipart/form-data` bodies into ordered text and File entries. It also has one stable response stream object, a bounded default `ReadableStream` reader with deterministic byte chunks, and `tee()` branches that lock the source body. A bounded in-memory `CacheStorage` stores immutable GET and HEAD response snapshots by named cache, and the browser-session store survives full-document navigation without opening a listener. Full stream backpressure, BYOB readers, and wiring native transport into a production navigation queue remain separate gates.

An optional `native-http` feature now supplies a Rust-native HTTPS `ResourceProvider` with platform certificate verification, connection reuse, a 30-second timeout, and automatic redirect suppression so the engine retains redirect policy. Navigation follows a bounded chain of same-origin relative locations, rejects cross-origin locations, and consumes provider responses with their HTTP status, so upstream 404 and 503 failures reach the typed recovery page without extensionless shell fallback. Redirected modules resolve relative imports from their final URL. The new bounded `EngineWorker` owns `Browser` and `EngineHost` on a dedicated standard-library thread, and the native window adapter uses it for remote mode so blocking provider calls never run on the UI event thread. This proves a real transport adapter without making the renderer depend on CEF, Edge WebView2, or a loopback listener.

FormData values expose ordered key, value, and entry iterators, `forEach()`, and `Symbol.iterator`, including File values without collapsing them to strings.

URLSearchParams now exposes the matching ordered key, value, entry, `forEach()`, and `Symbol.iterator` surface, with mutations still synchronized to its owning URL.

The page runtime now has a bounded `Worker` boundary for classic and module entry scripts. A same-origin entry script from packaged assets or the embedder-owned `ResourceProvider` runs on a dedicated standard-library thread. Classic Workers can call sequential `importScripts()`, while module imports or `fetch()` calls inside either Worker type use the same packaged-first policy. Provider requests cross a bounded channel and are serviced by `Browser::pump()` or `EngineHost` on the engine thread, so the worker resource path stays independent from a loopback listener. The worker receives bounded structured-cloned messages through `self.addEventListener()` or `self.onmessage` and replies through `postMessage()`. The page receives `addEventListener()`, `onmessage`, and `onerror` events and can call `terminate()`. Transfer lists, cycles, shared-reference identity, and nested workers remain separate compatibility gates.

The custom runtime now has a bounded WebAssembly path that consumes fetched `ArrayBuffer` bytes through `WebAssembly.instantiate()`. It parses version 1 modules with defined i32 functions, named function exports, calls, locals, arithmetic, comparisons, and bitwise operations, and returns a promise with `module` and `instance.exports` objects. Imports, memory, tables, globals, floating-point values, SIMD, threads, streaming compilation, and unsupported control flow are rejected before execution. This is a narrow execution slice, not general WebAssembly compatibility.

The renderer now has a matching bounded layout, paint, element-scrolling, and document-scrolling gate for positioned application chrome. `position: relative` establishes a containing-block marker, keeps the box in normal flow, and applies a visual offset to its subtree. Vertical `position: sticky` descendants also remain in flow, then receive a bounded visual correction against the nearest scrollport with a containing-block clamp. `absolute` descendants leave normal flow, `fixed` descendants anchor to the viewport, and pixel or percentage `inset` values resolve against the selected block. Positioned boxes accept bounded integer `z-index` ordering within each layout parent, and positioned z-index boxes and fixed boxes are painted and hit-tested as atomic stacking layers. `overflow: hidden`, `overflow: clip`, and `overflow: auto` clip software paint and coordinate hit testing together. Automatic-overflow boxes track bounded horizontal and vertical offsets, reserve a classic-style 12px scrollbar gutter, paint software tracks and thumbs, expose `scrollTop` and `scrollLeft`, while the document exposes `window.scrollX`, `window.scrollY`, `pageXOffset`, `pageYOffset`, `scrollTo()`, and `scrollBy()`. Both paths accept host wheel input and dispatch `scroll` events. Horizontal and inline sticky descendants, full sticky containment semantics, complete CSS stacking-context semantics, smooth scrolling, and scroll snapping remain separate gates. The gutter is reserved after this bounded layout pass, so it does not claim full CSS reflow compatibility. The behavior follows the containing-block, sticky view rectangle, scrollport, visual-view, scrollbar, and stacking-order concepts in the [CSS Positioned Layout Module Level 3](https://www.w3.org/TR/css-position-3/), [CSS Overflow Module Level 3](https://www.w3.org/TR/css-overflow-3/), and [CSSOM View Module](https://www.w3.org/TR/cssom-view/).

An experimental backend must pass these gates in order:

### Boot and origin

- starts without a loopback listener
- loads the exact app origin from packaged assets
- serves modules, styles, JSON, WebAssembly, fonts, images, and workers
- returns an app-owned recovery document for missing routes and load failures

### Web application surface

- ES modules and same-origin dynamic import
- `fetch`, streams, `URL`, `URLSearchParams`, and `AbortController`
- localStorage and bounded Web Crypto digests
- workers, timers, `requestAnimationFrame`, and WebAssembly
- CSS grid, flexbox, container queries, forms, focus, selection, and IME
- positioned overlays, containing blocks, overflow clipping, scrolling, stacking contexts, and z-order
- canvas 2D, WebGL, and WebGPU where the target platform exposes them

### Product integrations

- audio and video playback
- MSE and WebRTC capability reporting
- native clipboard and file-picker UI adapters
- accessibility tree delivery
- popup, permission, fullscreen, download, and authentication decisions
- crash, reload, and recovery behavior

### Platform and security

- Windows, macOS, and Linux x64 first
- ARM64 after the desktop contract is stable
- sandbox or equivalent process restrictions
- no renderer access to the asset root outside the native boundary
- reproducible resource packaging and an upgrade path for engine security fixes

The removed CEF build remains the measured baseline. Any engine claim must report pass counts and failures against the same pages, startup time, first usable frame, steady-state memory, renderer crash recovery, and bundle size. A speed claim is not valid until the workload and engine versions are pinned.

The current measurements were taken on Windows x64 release builds of this repository, rendering `web/index.html` at 1120x720: 5.7 MB bundle, 9 files, one process, a 28 MB working set four seconds after launch with the page animation running, about 430 ms median from process start to a written PNG of the first frame including font discovery, and 2.7 ms per animating frame at the median of 300. That frame time started at 39.1 ms before the stylesheet cache, the rule index, the borrowed cascade and the opaque span fills, and dropped from about 3.4 ms to 2.7 ms when style matching moved onto the node arena. The CEF bundle of the same app measured 411 MB, 252 files, six processes and 319.7 MB resident. Startup for the CEF path is not instrumented, so no startup comparison is claimed.

It also orders positioned siblings by bounded integer `z-index` within each layout parent, using atomic stacking layers for positioned z-index boxes and fixed boxes in both software paint and coordinate input. Automatic overflow reserves a bounded classic-style scrollbar gutter, paints software tracks and thumbs, routes wheel input from the gutter to the owning scroll container, and drags the thumb with the pointer while it stays grabbed at its press offset. Horizontal and inline sticky descendants, full sticky containment semantics, and complete CSS stacking-context semantics remain separate gates.

The experiment is useful even when a gate fails. A failure at a named gate tells us whether Ceri's stable contract is missing an abstraction. A passing slice gives us a measured basis for deciding whether to grow the custom engine or use Servo for that layer.

The file-input boundary now sits beside that headless form path. A host-owned `FilePicker` returns validated file metadata and bytes, while `input.files` exposes a bounded `FileList` view and multipart submission preserves the selected `File` entries. The renderer sees a fake path display value and never receives the host filesystem path.

The clipboard boundary now sits beside it. A host-owned `ClipboardProvider` supplies text through `navigator.clipboard.readText()` and `writeText()` promises, while permission and platform failures remain typed at the embedder boundary. The renderer never receives a native clipboard object.

Transforms now cover the full function list. `transform` accepts every `translate`, `scale`, `rotate`, `skew`, `matrix`, `matrix3d` and `perspective` form, the individual `translate`, `rotate` and `scale` properties apply before it in that order, and `transform-origin`, `perspective`, `perspective-origin` and `backface-visibility` are honoured. A pure translation still moves the subtree through the visual offset that relative positioning uses, so the common case costs nothing extra; any other transform makes the box a stacking context, paints its subtree into a layer at the resolution it will be shown at, up to four times the device scale so scaled text stays sharp, and composites that layer by pulling every covered pixel back through the inverse projection with bilinear sampling, which also antialiases the edges. Clicks, hover, wheel targets, scrollbar thumbs, text controls and prose selection map the pointer into the transformed space the same way, and absolute and fixed boxes now apply their transforms too. Translations still animate through keyframes and transitions; animating the other functions arrives with the interpolation work that follows.

Animation now covers the properties apps reach for. Two declared values blend whenever they have the same shape: numbers and colors mix pairwise inside shadows, gradients, positions, transform functions and anything else, a bare zero takes the other side's unit, and different length units meet in `calc()`. A `transform` of `none` blends as the identity form of the other side's functions, and lists that do not line up go through a 2D matrix decomposition into translation, rotation, shear and scale, taking the shorter way round. Thirty-nine properties are animatable, `transition: all` is one entry rather than a fan-out that ran out of slots, and each running transition keeps its own timing. Timing uses real `cubic-bezier()` curves, solved by Newton steps with a bisection fallback, plus `ease-in`, `ease-out`, `ease-in-out`, `step-start`, `step-end` and every `steps()` jump position. Keyframe animations now run from the moment an element gains them instead of from page load. Pages receive `transitionrun`, `transitionstart`, `transitionend` and `transitioncancel`, and `animationstart`, `animationiteration`, `animationend` and `animationcancel`, with `propertyName`, `animationName` and `elapsedTime`. Sampling checks only rules that declare motion before running a cascade, and style state no longer clones the document for every form control, so the packaged app's frame time held steady while all of this was added.

Opacity below one now fades a subtree as a group. The box becomes a stacking context, its descendants paint into a transparent premultiplied layer sized to what the subtree can reach, and the layer composites once at the box's opacity, so a child covering its parent hides the parent instead of mixing with it, nested groups multiply, and text, images, canvas output and scrollbars inside the group fade together. A single box whose own paint cannot overlap itself skips the layer and fades its fills directly, and layer buffers are pooled across frames, so the packaged app's frame time is unchanged. Inline elements with opacity still fade their own glyphs individually.

Raster images now decode without an image library. An engine-owned inflater feeds a PNG decoder that covers every color type, bit depth, filter and Adam7 interlacing, a JPEG decoder covers baseline and progressive Huffman files with any sampling factors, restart intervals, Adobe CMYK and EXIF orientation, and a GIF decoder takes the first frame. Measured on Windows x64 release builds, a 3000x2000 JPEG decodes in 86 ms baseline or 93 ms progressive, and the same picture as PNG in 56 ms; decoded pixels stay within 3 levels of libjpeg's output on the test set. Every decoder checks the declared size against the decode limit before it allocates, and truncated or corrupted files fail with a typed error rather than a panic. Images are cached per document, sized from their natural dimensions, placed by `object-fit`, and painted with bilinear sampling, opacity and rounded clipping. `background-image` with position, size and repeat uses the same path, and images and `inline-block` boxes now sit on text lines. WebP, animated frames, `object-position` and multiple background layers remain gates.

Generated content now builds inside flex and grid containers as well as the block path. A container's `::before` or `::after` box joins the flex line or the next free grid track with its own styles, so badges and markers no longer disappear when a list switches to flex or grid layout. Generated content still cannot become an anonymous inline fragment inside text, which remains a separate gate.

The future-gate list treats full WebAssembly compatibility as unfinished. The bounded i32 module path above is a separate tested slice and does not change that boundary.
